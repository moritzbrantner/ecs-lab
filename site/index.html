Comparison method

Optimize implementations, not semantics

The lab separates the question “what should this workload mean?” from “which storage or compute strategy executes it best?” so faster candidates can be checked mechanically.

  1. 01Workload

    Generate deterministic entity/component and physics operations.

  2. 02Reference

    Replay them in the simple BTreeMap-backed semantic oracle.

  3. 03Candidate

    Replay the same work in sparse-set, archetype, or future designs.

  4. 04Parity

    Compare snapshots or collision bitsets before considering performance.

  5. 05Measure

    Benchmark named scenarios with reproducible environment metadata.
